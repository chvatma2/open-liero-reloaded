# Plan 13d: Pack Tooling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give people, agents and the coming editors tools to author native packs: `olr-cli pack check|fmt|new`, the `olr-cli level` operations with a preview, and generated schema docs with a hand-written guide.

**Architecture:**
- A new crate, `olr-edit` (layer 3), holds the operations library the editors will share:
  - loading and saving a pack's authoring source;
  - the canonical formatter;
  - pack templates;
  - the level operations.
- `olr-cli` (layer 6) wires the commands.
- The validator stays `olr_pack::validate`, gaining warnings for unknown files and for objects outside the level.
- Every save replaces the pack directory as a whole: it writes a hidden copy, then swaps it in. The swap helper moves from `olr-import` into `olr_pack::install`, so both use it.
- Schema pages are generated by `cargo xtask format-docs`. It uses `syn` to read `olr-format`'s authoring types, their doc comments and their serde defaults. `cargo xtask check` fails when the committed pages drift.

**Tech Stack:** Rust 1.99, clap, serde/ron through `olr_format::ron_io`, `syn` (in xtask), proptest.

**Spec:** `docs/superpowers/specs/2026-10-16-formats-design.md`, §6 (validation, schema docs, agent operations) and §9 (13d, amended by plan 13c).

## Global Constraints

- Never panic on content (repo rule 6). Inputs from packs, images and command lines are untrusted.
- Keep output deterministic (repo rule 7). Iterate a `BTreeMap`, never a `HashMap`, when producing output.
- One crate per concern. Register `olr-edit` in `xtask/layers.ron` at layer 3, with a `CLAUDE.md`. Its integration tests form one binary (`autotests = false`).
- Learn a dependency's API from `cargo xtask api` and `target/api/<crate>.txt`.
- Canonical text goes only through `olr_format::ron_io::{to_canonical, from_canonical}`. Writers never produce non-canonical files.
- `PACK_FORMAT_VERSION` stays 5. This plan changes no file format, so `content/packs` must not change.
- These must stay byte-identical: the oracle traces, the match goldens, the render goldens, `crates/olr-cli/tests/snapshots/` (the digest) and `content/packs/`. Never bless them in this plan.
- Compatibility breaks are fine: `olr-cli validate` is removed, not aliased.
- Verify once per batch. Run targeted `cargo nextest run -p <crate>` while working, and the online `cargo xtask check` at the end of each batch:
  - Batch A is Tasks 1–4.
  - Batch B is Tasks 5–6.
  - Batch C is Tasks 7–9.
  - Task 10 is docs only and needs no check.
- **No `cargo xtask full`, bench or stress in this plan.** It touches no simulation, rendering, audio, network or performance code. Benchmarks also need the user's explicit agreement.
- Commits are small, with an imperative subject (`olr-edit: …`), and end with the session's two trailer lines.

## Review Focus

1. **Foreign files in a pack directory.** Examples are an editor's backup (`level.ron~`), `.DS_Store` and a README.
   - `pack fmt` and the level operations keep them byte for byte.
   - `pack check` warns about each one, naming it.
   - Tests: Task 2 (`warns_about_files_the_format_does_not_read`) and Task 3 (`fmt_keeps_foreign_files`).
2. **A save that fails halfway** (invalid result, write error, killed process).
   - The pack on disk is either the old pack or the new one, never a mix.
   - An invalid result writes nothing.
   - Tests: Task 1 (`a_failed_write_leaves_the_old_pack`) and Task 6 (`an_invalid_operation_writes_nothing`).
3. **Shapes partly or wholly outside the level, zero or negative sizes, huge radii.**
   - Shapes are clipped. An empty intersection is a no-op that still saves an unchanged pack. Arithmetic never overflows.
   - Test: Task 5 (`shapes_outside_the_level_are_clipped_never_panic`).
4. **Levels at `art_scale` above 1.**
   - Every world pixel an operation touches changes its whole `art_scale × art_scale` art block.
   - `front` equals `back` wherever the material is background, before and after every operation.
   - Test: Task 5 (`the_background_invariant_holds_at_every_art_scale`, a proptest).
5. **`pack new` aimed at an existing or non-empty directory, or given an id that is not a slug.**
   - The command is refused, and nothing is written.
   - Test: Task 4 (`refuses_an_existing_directory_and_a_bad_id`).

## Rulings made while writing this plan

- **R1 `olr-edit` at layer 3.** It depends on `olr-format`, `olr-pack`, `olr-vfs` and `olr-data`, all at layer 2 or below. The editors (layer 5/6) will use it. It is not a forbidden importer, so the game may link it later.
- **R2 Whole-pack replace.** A save writes the complete new pack into `<parent>/.import-<dirname>` (`olr_pack::install::TMP_PREFIX`).
  - It moves the old pack to `.replaced-<dirname>` and renames the new one into place, then removes the old one.
  - This is the importer's procedure, moved into `olr_pack::install::replace_dir` so both share it.
  - Foreign files are copied into the new pack, so nothing is lost.
  - It also settles `olr-format`'s note that "a later save path must clear the mod files first": files the source no longer has are not copied.
- **R3 What the level operations mean.** They work on `olr_format::levels::LevelSource`, in world pixels.
  - `carve`: the material becomes background, and `front := back` on the covered art blocks.
  - `fill`: the material becomes rock or dirt, and `front` is painted with a colour or a tile image.
  - `paint`: art only. Painting `back` also paints `front` where the material is background. Painting `front` touches only solid pixels.
  - `stamp`: alpha-composites a PNG onto an art layer at an art-pixel position given in world pixels × `art_scale`, with the same layer rule as `paint`.
  - `resize`: a new size and an offset for the old content. The new area gets a material and a paint. Objects move with the content, and objects that fall outside are dropped with a warning.
  - `object add|move|remove|list`: objects are addressed by their index in `objects`.
  - Every operation regenerates `thumb.png` from `front` (`olr_format::levels::thumbnail`, moved from `olr-import-gfx`).
  - The spec's `stamp` is open, and the theme's stamps are carving shapes for the simulation, so the image stamp is the editor's tool.
- **R4 Schema docs come from the code.** `cargo xtask format-docs` reads the authoring types with `syn`:
  - each serialized field's name and type, and its doc comment, which already states its unit and OLX source;
  - its default, from the `#[serde(default = "d::…")]` function's value in `defaults.rs` or the type's `Default`;
  - its limits, from the doc comment and the bound constants.
  - A field or variant without a doc comment fails the generator. That is the completeness check.
  - **Examples are one per type, not one per field.** Each type section shows a canonical snippet taken from the guide's complete examples. A per-field example would repeat the default or the type. This deviates from spec §6, and Task 10 records it there.
- **R5 `pack fmt --check` in `check`.** It runs as an `olr-cli` test (`bundled_packs_are_canonical`) through the `olr-edit` library. That test runs inside `cargo xtask check`'s nextest step, which satisfies spec §6 ("`cargo xtask check` runs `--check` over `content/packs`") without a new xtask step.
- **R6 `pack new` templates.**
  - `mod` and `level` are generated from code: a one-weapon mod, and a level of a given size whose material is all dirt with a rock border, front dirt-brown, back near-black.
  - `skin`, `theme` and `core` require `--from <pack dir>`. They copy that pack's authoring source under the new id and name. `--from` works for every kind.

**Interfaces:**
- Produces, in `olr_pack::install`:

  ```rust
  /// Replaces the directory `dir` with what `write` puts into a fresh
  /// hidden sibling (`<parent>/.import-<name>`): the old directory is
  /// renamed aside (`.replaced-<name>`, `~k` when taken), the new one
  /// renamed into place, the old one removed. `write` failing removes the
  /// sibling and leaves `dir` untouched. Returns warnings (an old copy that
  /// could not be removed).
  pub fn replace_dir(
      dir: &Path,
      write: impl FnOnce(&Path) -> std::io::Result<()>,
  ) -> std::io::Result<Vec<String>>;
  ```

- Produces, in `olr_edit::pack`:

  ```rust
  pub enum Source {
      Mod(olr_format::mods::ModSource),
      Level(olr_format::levels::LevelSource),
      Skin(olr_format::skins::SkinSource),
      Theme(olr_format::themes::ThemeSource),
      Core(olr_format::core_pack::CoreSource),
  }
  pub struct Pack {
      pub manifest: olr_data::manifest::PackManifest,
      pub source: Source,
      /// Files the format does not read (foreign files, and a mod's
      /// gfx/sounds assets), by path, kept byte for byte.
      pub other: std::collections::BTreeMap<olr_vfs::VPath, Vec<u8>>,
  }
  pub fn load(dir: &Path) -> Result<Pack, olr_pack::PackError>;
  /// Every file of `pack` as its canonical writer produces it
  /// (`pack.ron` and the kind's files), plus `other` as it is.
  pub fn files(pack: &Pack) -> Result<BTreeMap<VPath, Vec<u8>>, olr_pack::PackError>;
  /// `files(pack)` written through `replace_dir`; the result is read
  /// back with `olr_pack::validate` before the swap, and an error there
  /// aborts the save (the old pack stays).
  pub fn save(dir: &Path, pack: &Pack) -> Result<Vec<String>, SaveError>;
  ```

  `load` reads the manifest with `olr_pack::read_manifest`, then the kind's `olr_format::*::read_*_files`. Use `read_level_files`, which keeps the thumbnail. `other` is every walked path the kind's writer would not produce: write the source to a `MemFs`, take its paths and `pack.ron` away from the walk, and keep the rest.

  ```rust
  pub fn fill(level: &mut LevelSource, shape: &Shape, solid: Solid, paint: &Paint);
  pub fn paint(level: &mut LevelSource, shape: &Shape, layer: Layer, paint: &Paint);
  /// `image` in art pixels, its top-left at world (x, y) × art_scale.
  pub fn stamp(level: &mut LevelSource, at: (i32, i32), image: &RgbaImage, layer: Layer);
  /// The old content's (0, 0) lands at `offset`; the new area is `material`
  /// painted with `paint` (front and back alike when background). Objects
  /// move by `offset`; those now outside are removed and returned.
  pub fn resize(level: &mut LevelSource, size: (u32, u32), offset: (i32, i32), material: Material, paint: &Paint)
      -> Result<Vec<LevelObject>, EditError>;
  pub fn add_spawn(level: &mut LevelSource, at: (i32, i32), notes: &str) -> Result<usize, EditError>;
  pub fn move_object(level: &mut LevelSource, index: usize, at: (i32, i32)) -> Result<(), EditError>;
  pub fn remove_object(level: &mut LevelSource, index: usize) -> Result<LevelObject, EditError>;
  /// Regenerates `thumb` from `front` (every CLI operation calls it).
  pub fn refresh_thumb(level: &mut LevelSource);
  ```

  Rules:
  - A `Shape` covers the world pixels whose centre lies inside it. For a `Rect`, that is `x <= px < x + w`; `w <= 0` covers nothing. For a `Circle`, it is `(px - cx)² + (py - cy)² <= r²`, computed in `i64`; `r < 0` covers nothing.
  - Clip to the level before iterating, so a huge shape costs at most the level's area.
  - A `Tile` repeats from the art origin (art pixel `(ax mod tw, ay mod th)`). A zero-sized tile is refused at parse time in the CLI; the library treats it as no paint.
  - `EditError` covers a size outside `1..=MAX_SIDE`, more than `MAX_OBJECTS` objects, an index out of range, and art over `LEVEL_ART`.
